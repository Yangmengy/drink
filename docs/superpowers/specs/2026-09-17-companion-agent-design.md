# 陪伴式调酒 Agent：已确认设计

用户已在对话中确认本方案及实施。保留 Tauri、React、ADK-Rust 和本地 SQLite；不建立账号或云服务器。云模型直接调用用户配置的兼容 API。

## 用户体验

四个入口：聊天、酒柜、自定义、设置。聊天是首页，主 Agent 自然陪伴，只有需要酒品知识或推荐时才调用工具。不设置独立意图分类 Agent，不强制选择心情或天气，不以负面情绪为理由劝酒。

酒柜包含原料和酒单两个视图。自定义页支持新增和编辑配方，原料名称、用量、单位、制作步骤、风味为结构化字段。保存后自创酒立即进入同一个菜单库。拥有配方不代表拥有原料。

## 工作流和约束

主 Agent 按上下文选择工具。菜单工具并行读取菜单与库存，Rust 计算必需原料的缺失情况；可选原料单独标注。查询同时覆盖内置和自创配方，中文查询使用子串匹配，不直接把输入当作 FTS 语法。

工具返回完整配方及缺料事实；Agent 选择候选并用陪伴语气解释。推荐卡片的 ID 必须来自本轮工具结果，未知或未检索 ID 不得进入卡片。材料未知时不得假定具备，缺料候选仍可展示。只有材料种类库存，不宣称已经核验剩余用量。

设置保存昵称、自由文本口味偏好、模型名、API 地址及密钥。MVP 通过明确的表单维护库存和长期偏好，聊天表达用于当前上下文，不把随口一句话自动写成永久库存事实。

## 模块

- React：四页面、统一类型和 IPC 入口、配方卡片与详情。
- Rust menu：菜单查询、自创配方事务、库存与缺料计算。
- Rust agent：ADK LlmAgent、只读菜单工具、受约束输出、会话管理。
- Rust db：首次启动、版本化迁移、旧目录兼容、明确列名的种子数据。
- Rust settings：本地配置读写；前端只读取是否设置密钥，避免普通资料读取返回密钥。

ADK session 是聊天上下文和展示历史的统一来源；旧 memory 数据库不再写入但保留文件。清空聊天会清空实际 session。聊天请求串行，失败显示可重试错误，避免重复提交；不把工具异常伪装成无结果。

## 清理边界

微信小程序移动到仓库外归档。移除旧 UI、待办/打卡/背景/星座推荐业务和硬编码密钥测试脚本。ADK 上游目录整体保留，只缩减应用启用的 features。已有 SQLite 用户数据不删除，已停用业务的旧表留存。旧设计文档归档。签名文件移至仓库外私有归档，不重写 Git 历史。

## 验收

1. 空库能初始化且内置菜单可查询；重复启动幂等，旧自创酒和库存保留。
2. 新增、编辑配方能完整保存原料和步骤；同一查询立即召回自创酒。
3. 无库存、部分库存、全部库存及可选材料正确计算；中文及特殊字符查询安全。
4. 主 Agent 的工具结果进入推荐，未知 ID 拒绝；普通聊天无需菜单工具。
5. 对话重启可恢复，清空后模型上下文同样清空。
6. 四入口可操作，窄屏无横向溢出，错误、加载、空态可见。
7. 前端生产构建、Rust 检查及关键集成测试；使用本地模拟模型验证 ADK 工具链，不使用仓库内泄露密钥。
