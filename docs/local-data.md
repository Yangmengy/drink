# 本地数据与兼容边界

当前应用面向个人桌面使用。业务数据不依赖云服务器；设置的模型服务商仍会收到必要的聊天上下文和工具结果。

## 文件及所有权

macOS 默认目录为 `~/Library/Application Support/cocktail-app/`。设置页会显示实际目录。调试版可用 `MIXOLOGY_DATA_DIR` 指定隔离目录，发布版忽略这个变量。

| 存储 | 当前用途 | 维护者 |
| --- | --- | --- |
| `cocktail.db` | 菜单、原料、库存、设置、trace | 应用的 `db` 模块 |
| `cocktail-chat.db` | 聊天历史和最近 20 轮模型上下文 | ADK SQLite SessionService |
| `.model-key` | 模型 API Key，独立明文文件，Unix 权限 0600 | `settings` 模块 |
| WebView localStorage | 当前主题 | 现有前端主题模块 |
| 当前窗口内存 | 聊天输入、自创配方草稿、酒柜搜索与筛选 | 前端共享状态 |
| 旧 `cocktail-memory.db` | 历史文件，当前不读写 | 用户自行保留 |

应用数据库迁移不处理 ADK 会话库。清空聊天会删除实际 ADK session；业务库中的 trace 独立保留最近 100 轮。

切换页面会保留聊天输入和每份自创配方草稿；刷新或关闭应用不会保留这些未保存的内容。自创配方保存成功后才清除对应草稿，保存失败可以继续修改或重试。聊天推荐卡片跟随当前酒柜更新，历史聊天文字保持原样；已删除的自创酒只作为历史配方展示，不再宣称可制作，也不会参与新的召回。

## 新建数据库

只创建 8 张核心表：`recipes`、`ingredients`、`recipe_ingredients`、`recipe_steps`、`user_inventory`、`companion_settings`、`agent_traces`、`core_migrations`。

配方仅保存 ID、中英文名称、分类、描述、方法、风味、图片、来源和创建/更新时间，共 11 个字段。新库没有收藏、浏览次数、同步时间、情绪、星座、打卡或 FTS 表。库存只记录材料有无。

`src-tauri/data/seed.sql` 是唯一的初始菜单来源。它与 Schema 使用显式列名，与旧库列顺序无关；内置数据保持 83 款酒和 161 种材料。菜单图片中没有重复或无引用文件。

## 支持的升级路径

| 输入 | 处理 |
| --- | --- |
| 空库 | 在事务中创建核心表、导入种子数据、写入版本 1 和 2 |
| 原始 33 列或扩展 40 列桌面旧库，无核心版本号 | 校验必要表/字段，补入尚不存在的内置记录，导入旧模型配置，升级到 2 |
| 核心版本 1（2026-09-17） | 保留菜单、库存、设置和 trace，只完成版本 2 迁移 |
| 核心版本 2 | 幂等打开，不重新灌入菜单、不覆盖现有设置 |
| 版本高于 2、缺少必要字段/表、迁移记录断裂、配置记录缺失、其他应用的库 | 明确报错；不创建或修改业务表，不自动重置数据 |

结构检查在写入前完成，建表、播种和版本记录在同一事务中提交。中途失败整体回滚。兼容范围是项目已知桌面结构；任意第三方库、损坏文件和旧移动端缓存不承诺自动导入。

## 有意保留的历史数据

- 已有库的额外列和旧业务表原样留存，不执行 `DROP TABLE` 或删列。新 Schema 的精简不会反向删掉旧库中的故事、收藏、原料剩余量或打卡记录。
- 版本 2 移除三个旧 `recipes_fts_*` 同步触发器。旧 FTS 表作为历史快照保留；当前查询使用菜单工具的子串与风味筛选。
- 旧 `user_profile` 的昵称、模型名、基础 API URL 只在首次核心迁移时导入。MBTI、星座、天气和旧待办不进入主 Agent 上下文。
- 旧 `user_profile.llm_api_key` 单独迁移：只有本地密钥文件不存在时才写入；写入成功或已有文件后才清空旧字段。已有 `.model-key` 优先，不用旧值覆盖。
- 密钥文件与业务库不在同一 SQLite 事务中；迁移可以重复执行。密钥文件未加密，Git 不跟踪它。
- ADK 对话在内存中完成后才保存已校验结果。用户消息与回复是两次 ADK 写入，不宣称跨文件或整轮写入具备原子性。

保留旧数据是兼容边界，不代表仍提供这些历史功能。升级后不保证旧应用能完整理解新配方和设置；回退应使用升级前的完整备份。

## 备份与恢复

退出应用后，复制整个数据目录到自己的备份位置，包含隐藏的 `.model-key` 和可能存在的 SQLite `-wal` / `-shm` 文件。不要只复制一个数据库；会话、菜单与密钥分别存储。

恢复时同样先退出应用，保留现目录的副本，再用备份替换。主题来自 WebView localStorage，不包含在这份目录备份中，可以重新选择。

仓库外 `drink-archive-20260917/` 与 `drink-archive-20260918/` 是代码和历史材料归档，不是个人数据库备份。本次清理不打开或迁移真实个人数据，测试只使用内存库和临时目录；实际升级发生在下一次启动应用时。
